## 2. Open questions (need Albert / team)

| ID | Question | Why it matters / lean |
| --- | --- | --- |
| Q3-1 | **Enrich via X API + "summary"** conflicts with two standing rules: D-09 *no LLM anywhere* (a summary of tweets is an LLM call) and D-02/D-13 *static site, no backend, no runtime fetches*. Which do we relax? Options: (a) offline pipeline step, cached into `dossiers/*.json`, no live button (keeps both rules); (b) a Next route handler + X API key + LLM at runtime (needs hosting env vars on Vercel, X API paid tier, breaks "no LLM"); (c) drop Enrich, keep VoteSmart only. | Blocks child F. Lean: (a) for base + a cached "enrichment" per issue; live prompted Enrich only if we accept a backend. |
| Q3-2 | **VoteSmart** API needs a key (application-approved, non-trivial turnaround) — do we have one? Fallback: scrape the public candidate page, or keep congress.gov/senate.gov as base and add VoteSmart later. | Blocks child F. |
| Q3-3 | Top-level label: "Stances" or "Policies"? And what was **"Media"** in "Ledgers, Ads, Media, Policies" — is that the ads media wall (already `Ads`) or a separate tab? | Nav copy for child A + E. Lean: Ledger · Ads · Stances. |
| Q3-4 | **Funder ↔ stance mapping** semantics. `issue_focus` has `issue_ids` (topic) but no *direction*; a candidate's stance has `direction`. Do we (a) show "funders focused on this issue" + their support/oppose of the candidate (no alignment claim, all on file), or (b) hand-code a `direction` per funder issue (additive contract field) so we can say "aligned"? (b) is an inference we'd have to label (`basis: inferred`). Only 34 spenders have `issue_focus` today. | Defines child E. Lean: (a) first, (b) as a hand file if time. |
| Q3-5 | **"Money received from entities that support this"** — super PACs never give to the campaign (targeting, not money). For T2 do we show (i) PAC contributions to the campaign committee from `entities/<campaign>.json.inflows`, (ii) IE support dollars, or both in separate columns? | Lean: both, separately labelled. |
| Q3-6 | Pie P3 for **campaign receipts**: receipts have no support/oppose. Slices = individuals / committees / other (per candidate)? Or one chart per candidate showing receipts vs outside? | Child B needs this; default: individuals (incl. conduit note) / committees / other. |
| Q3-7 | Card **category dropdown** — derived categories = story kinds (`biggest_spender`, `dark_dead_end`, `popup`, `single_transfer`) and/or `issue_focus.kind` (`general_partisan`, `single_issue`, `business_trade`, `labor`, …)? | Default: both groups in one dropdown, grouped, each with a one-line description. |
| Q3-8 | With Stories tab cut, does `/races/[raceId]/stories` 404 or redirect to the ledger? Same for `/vendors`. | Default: delete the list pages; keep `vendors/[vendorId]` detail. |
| Q3-9 | Should the merged card grid be built from `top_outside_spenders` (98, complete) with story kinds as badges, rather than from `stories.json` (18)? | Lean: yes — cards per spender; story data only decorates. |
| Q3-10 | Sankey **hover** with ad thumbnails: only ads with `cached_creative_path` (26 of 50 top video ads) have images. OK to show name-only hover for the rest? | Default yes. |
